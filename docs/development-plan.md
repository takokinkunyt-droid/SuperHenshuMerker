# スーパー編集メーカー 開発計画書

Oct 9, 2026 · @たこきん

## 概要と目的

ゆっくりボイス（AquesTalk）を載せない軽量版「スーパー編集メーカー」として、ブラウザだけで「立ち絵＋字幕＋読み上げ音声」の解説動画を作れる編集ツールを作る。インストール不要で、Windows以外の環境でも使えることが最大の価値になる。

- **想定ユーザー**：Mac・Chromebook・iPadなどYMM4が動かない環境の人、まずインストールなしで試したい初心者
- **位置づけ**：公式のYMM4Lite（AquesTalkを外した版）よりさらに軽い、ブラウザ版。YMM4公式とは無関係の独自ツールで、製品名やロゴにYMM4を使わない
- **MVPの成功基準**：台本テキストを入力し、キャラごとの音声・立ち絵・字幕が自動で並び、1080pのMP4として書き出せること
- **性能目標（仮）**：10分の動画をミドルスペックのノートPCで、編集中のプレビューが30fps前後で動き、書き出しが実時間の2倍以内に終わる

## 機能スコープ

MVPは「台本→ボイス→立ち絵・字幕→書き出し」の一本道に絞り、エフェクトやプラグインは後回しにする。YMM4は現在v4.4x系で、有志のコミュニティプラグインによる機能追加も続いているため、全機能の再現は目指さない（[v4.41.0.0リリースノート](https://manjubox.net/ymm4/release/4.41.0.0)）。

| 機能 | YMM4での中身 | ウェブ版 |
| --- | --- | --- |
| セリフ入力 | キャラを選んでセリフを入力すると、ボイス・字幕・立ち絵が連動して追加される | MVP |
| タイムライン | 複数レイヤーにアイテムを並べ、移動・伸縮・分割する | MVP（レイヤー、移動、伸縮、分割のみ） |
| プレビュー | 再生位置の画面をリアルタイム表示 | MVP |
| 音声合成 | AquesTalk（ゆっくりボイス）、VOICEVOXなど複数エンジン | VOICEVOX連携と音声ファイル読み込み。ゆっくりボイス（AquesTalk）は永久に対象外 |
| 立ち絵 | 画像・PSDのパーツを組み合わせ、口パク・目パチを付ける | MVPはPNGパーツの口パク・目パチ。PSD対応はフェーズ2 |
| テキスト・字幕 | フォント、縁取り、表示位置、文字送り | MVPは基本スタイル（フォント、色、縁取り、位置） |
| 画像・動画・BGM | 素材を読み込んでタイムラインに配置 | MVP（PNG/JPG、MP4、MP3/WAV） |
| 映像エフェクト | 登場退場アニメーション、クロマキー、イコライザーなど多数 | フェーズ2で頻出のものから（フェード、スライド、拡大縮小） |
| 図形・場面切り替え | 図形アイテム、トランジション | フェーズ2 |
| テンプレート | アイテム設定を保存して使い回す | フェーズ2 |
| 動画出力 | MP4などへエンコード | MVP（H.264＋AAC、MP4、1080p/30fps） |
| プラグイン | C#製のコミュニティプラグインで機能拡張 | 対象外。将来はJS製の独自プラグインAPIを検討 |
| YMM4プロジェクト読み込み | — | フェーズ3で検討（.ymmp形式の解析が必要） |

## 技術スタックとアーキテクチャ

サーバーを持たない静的ウェブアプリとして作り、編集・描画・書き出し・保存をすべてブラウザ内で行う。

> （図：アーキテクチャ · ブラウザ内6部品と外部の音声源3つ）

外部の音声はすべてプロジェクト状態に取り込んでから使う。レンダラー（強調）はプレビューと書き出しで同じ描画コードを使うので、見た目のずれが起きない。

| 層 | 採用案 | 理由 |
| --- | --- | --- |
| 言語・ビルド | TypeScript＋Vite | 入り組んだタイムライン状態を型で守る |
| UI | React（Svelteでも可） | タイムラインやパネル部品の資産が多い |
| 状態管理 | Zustand＋Immer | 変更差分からUndo/Redoを作りやすい |
| 描画 | Canvas 2Dで開始、エフェクト追加時にWebGL2 | MVPの立ち絵・字幕は2Dで足りる |
| 保存 | OPFS（素材）＋IndexedDB（プロジェクト） | 大きな素材をブラウザ内に置ける。ZIPで書き出し・読み込みも用意 |
| 配信 | 静的ホスティング＋PWA | 運用費がほぼかからず、オフラインでも動く |

## 音声合成とライセンス

スーパー編集メーカーはゆっくりボイス（AquesTalk）を一切載せない。音声は、ユーザーのPCで動くVOICEVOXへの接続と、音声ファイルの読み込みで用意する。

AquesTalkは、組み込むソフトの開発・使用・頒布それぞれにライセンスが要る（[AquesTalk1 Winマニュアル](https://www.a-quest.com/archive/manual/aqtk1_win_man.pdf)）。公式のYMM4LiteもAquesTalkを取り除いて配布されており、その状態なら商用・非商用を問わず無償で使える（[YMM4 FAQ](https://www.manjubox.net/ymm4/faq/etc/without-aquestalk)）。スーパー編集メーカーも同じ方針を取り、本体がライセンス問題を抱えない形にする。

ユーザーが他のツールで作った音声を読み込むことは止めないが、その音声の利用条件はユーザー側の責任とし、読み込み画面で一言案内する。

| 方式 | 仕組み | 長所 | 短所 | 時期 |
| --- | --- | --- | --- | --- |
| VOICEVOX連携 | ユーザーPCのエンジン（127.0.0.1:50021）にブラウザから接続。エンジンはCORS許可の起動オプションが必要（[参考](https://zenn.dev/megyo9/articles/82dee0167ab612)） | 無料、ずんだもん等の人気キャラ | エンジンを別途インストール。iPad・Chromebookでは不可。キャラごとにクレジット表記が必要 | MVP |
| 音声ファイル読み込み | 外部で録音・合成したWAV/MP3をセリフに紐づける | どの音声でも使え、全環境で動く | 1セリフずつ用意する手間。一括読み込みでカバーする | MVP |
| マイク録音 | ブラウザでセリフごとに自分の声を録る | 追加ソフト不要、iPadでも使える | 録音環境で品質が左右される | フェーズ2 |
| クラウドTTS | ユーザー自身のAPIキーでElevenLabs等を呼ぶ（YMM4もv4.41で対応） | インストール不要 | 有料。キーの扱いに注意 | フェーズ2 |

口パクは、生成済み音声の音量（RMS）を短い区間ごとに計算し、しきい値で口パーツを切り替える。これは方式に関係なく共通で使える。

## 動画の書き出し

書き出しはWebCodecsでブラウザ内エンコードし、MP4への格納は[Mediabunny](https://mediabunny.dev/)に任せる。サーバーで変換しないので、素材をアップロードさせずに済み、運用費もかからない。

WebCodecsは2026年3月のSafari 26.4で主要4ブラウザがそろい、Baselineになった（[Digital Samba](https://www.digitalsamba.com/blog/webcodecs-api-explained)）。ただしAACのエンコードはFirefoxと、デスクトップLinuxの全ブラウザで使えない（[MDN](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API/Codec_selection)）。MediabunnyはMPL-2.0で商用利用も可能で、エンコード可否を調べる関数と、独自エンコーダーの登録機能を持つ（[対応形式](https://mediabunny.dev/guide/supported-formats-and-codecs)）。

| 方式 | 中身 | 判断 |
| --- | --- | --- |
| WebCodecs＋Mediabunny | 1フレームずつ描画してハードウェアエンコード。実時間より速く書き出せる | 採用 |
| ffmpeg.wasm | FFmpegをWASMで実行。ソフトウェア処理で遅く、読み込みも重い | AAC非対応環境の音声だけを補う候補 |
| MediaRecorder | canvasを実時間で録画する | 不採用：実時間でしか録れず、コマ落ちする |
| サーバー側FFmpeg | 素材をアップロードしてサーバーで変換 | MVPでは不採用：費用と素材アップロードが発生 |

書き出しの流れ：

1. Web Worker内のOffscreenCanvasで、1/30秒ごとに全レイヤーを合成する（再生用と同じ描画コードを使う）
2. VideoEncoderでH.264にエンコードする
3. 全音声をOfflineAudioContextで1本にミックスし、AudioEncoderでAACにエンコードする
4. MediabunnyでMP4に格納する。長尺はStreamTargetでディスクへ逐次書き込み、メモリ不足を避ける

AACが使えない環境では、Opus音声のWebM（またはMP4）で書き出すか、音声だけWASMエンコーダーで補う。どちらにするかはフェーズ1の検証で決める。

## 開発フェーズとマイルストーン

最初の2週で「ブラウザで実用的な速さで書き出せるか」を確かめ、通ればMVPに進む。期間は1人・週末中心の開発を仮定した目安で、体制が決まったら引き直す。

> （図：ロードマップ · 4フェーズと3つのゲート）

各ゲートを通らなければ次に進まない。ゲートAで書き出しが遅すぎた場合は、解像度を720pに下げるか、書き出しだけサーバー処理にするかを判断する。

## リスクと対策

最大のリスクは技術より権利まわり（名称と素材の規約）で、次がブラウザのメモリと性能。権利はMVP前に、性能はフェーズ1の検証で潰す。

| リスク | 起きると | 対策 |
| --- | --- | --- |
| 読み込んだ音声の利用条件 | 利用者が規約違反の動画を作る | 本体は音声エンジンを同梱しない。読み込み時に利用条件の確認を促す |
| YMM4公式との混同 | 作者や利用者の誤解、苦情 | 製品名・ロゴにYMM4を使わず、説明文で公式とは無関係と明記。公開前に同名の既存サービスや商標がないか確認 |
| キャラ素材・VOICEVOXの規約 | 利用者が規約違反の動画を作る | 書き出し時にクレジット表記を自動生成し、規約リンクを表示 |
| 長尺動画でのメモリ不足 | タブが落ちる | 素材はOPFSに保存し、デコード済みフレームをキャッシュし過ぎない。書き出しはストリーム書き込み |
| プレビューのコマ落ち | 編集体験の悪化 | 描画をWorkerとOffscreenCanvasに分離。重いエフェクトはプレビュー時に簡略化 |
| ブラウザ差（AAC、Safari） | 一部環境で書き出せない | 起動時に対応状況を判定し、代替形式を案内 |
| データ消失 | 作業が消える | 自動保存、プロジェクトのZIP書き出し、ブラウザの永続ストレージ許可を要求 |

次の5点で計画の重みが変わるので、先に決めたい。

- [ ] 目的は個人用ツールか、一般公開するサービスか（公開なら権利確認と運用の項目が増える）
- [ ] 主な対象環境はどれか：Windows／Mac／Chromebook・iPad（iPad重視ならVOICEVOX連携の価値が下がる）
- [ ] マイク録音（自分の声）をMVPに入れるか
